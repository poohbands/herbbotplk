# ทำให้บอทตอบเร็วขึ้น (เป้าหมาย 30–45 วิ → ~5–12 วิ)

## สาเหตุที่ช้า (จากการอ่านโค้ด `supabase/functions/herbal-chat/index.ts`)

1. **ทุกขั้นตอนทำแบบเรียงต่อกัน (sequential)** — ดึง `herbs` → ดึง `thai_formulas` → ค้น `knowledge_documents` → ยิง PubMed 2 รอบ → (บางครั้ง) เรียก AI fallback → แล้วค่อยเริ่มตอบ เวลารวมกันหมด
2. **AI Fallback ใช้ `google/gemini-2.5-pro` แบบ non-stream** — เป็นตัวหนักและรอจนจบก่อนจะเริ่มตอบจริง ตรงนี้กินเวลามากที่สุด (จาก log: fallback ถูก trigger บ่อยมาก แม้คำถามต่อเนื่องสั้น ๆ เช่น "ขนาดในการกิน")
3. **PubMed เรียก 2 ครั้งต่อเนื่อง (esearch → esummary) โดยไม่มี timeout** — ถ้า NCBI ช้า ระบบรอไม่จำกัด
4. **ดึงทุกแถวของ `herbs` และ `thai_formulas` มาทั้งตาราง** ทุกครั้งที่ถาม แล้วค่อยมา match ในหน่วยความจำ

## แผนการแก้ (ไม่เปลี่ยนคุณภาพคำตอบ)

### 1. ทำงานขนานกัน
รวม `findRelevantHerbs`, `findRelevantKnowledge`, และ (เมื่อทำได้) PubMed ให้รันพร้อมกันด้วย `Promise.all` แทนการ `await` ทีละอัน

### 2. ใส่ timeout ให้ทุก external call
- PubMed: timeout ~4 วินาที (ต่อรอบ) ถ้าเกิน → ข้ามไป ไม่ให้บล็อกคำตอบ
- AI fallback: timeout ~8 วินาที
ใช้ `AbortSignal.timeout` ครอบ `fetch` ทั้งหมด แล้ว catch เป็นผลว่าง

### 3. ลดการใช้ AI Fallback ที่ไม่จำเป็น + เปลี่ยนโมเดล
- เปลี่ยนโมเดล fallback จาก `gemini-2.5-pro` → `gemini-2.5-flash` (เร็วกว่าหลายเท่า เพียงพอสำหรับสรุปบริบท)
- **ข้าม fallback** เมื่อคำถามเป็นคำถามต่อเนื่องสั้น ๆ (เช่น "ขนาดในการกิน", "มีข้อควรระวังอย่างไร") ที่มีประวัติสนทนาอยู่แล้ว — โมเดลหลักตอบต่อจาก context เดิมได้เลย ไม่ต้องรอ fallback
- ลดความยาวผลลัพธ์ fallback (จำกัด max tokens) ให้สั้นกระชับ

### 4. Cache ข้อมูลฐานข้อมูลใน memory ของ edge function
เก็บ `herbs` + `thai_formulas` ไว้ในตัวแปรระดับ module พร้อม TTL ~5 นาที — คำถามถัดไปในช่วงนั้นไม่ต้อง query DB ใหม่ (ตัดเวลาไปได้ทุกครั้งที่ instance ยัง warm)

### 5. ลด context ที่ส่งเข้าโมเดลหลัก
- ตัดเนื้อหา `knowledge_documents` ที่ยาวมากให้เหลือช่วงที่เกี่ยวข้อง (~1,500 ตัวอักษร/เอกสาร)
- จำกัดประวัติสนทนาที่ส่งไปเป็น 8–10 ข้อความล่าสุด
context สั้นลง = โมเดลเริ่มพ่นคำตอบเร็วขึ้นอย่างชัดเจน

### 6. UX ระหว่างรอ (ฝั่งหน้าเว็บ)
ใน `src/pages/ChatPage.tsx` แสดงสถานะเป็นขั้น ๆ ("กำลังค้นฐานข้อมูลสมุนไพร…", "กำลังค้นงานวิจัย…", "กำลังเรียบเรียงคำตอบ…") แทนจุดกระพริบเฉย ๆ เพื่อให้รู้สึกเร็วขึ้นและรู้ว่าระบบกำลังทำอะไร

## ไฟล์ที่แก้

- `src/pages/ChatPage.tsx` (สถานะระหว่างรอ)

- คำถามที่ต้องพึ่ง PubMed/fallback: ~8–15 วินาที (จากเดิม 30–45)
