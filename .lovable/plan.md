# ทำให้บอทตอบเร็วขึ้น โดยคงความถูกต้องและครบถ้วนไว้เท่าเดิม

## จุดที่ทำให้ช้า (ยืนยันจากโค้ด `supabase/functions/herbal-chat/index.ts`)

ปัจจุบันทุกอย่างทำแบบเรียงต่อกัน และผู้ใช้จะเห็นตัวอักษรแรก **หลังจากทุกขั้นตอนเสร็จหมดแล้ว**:

1. เรียก AI จำแนกเจตนา (บรรทัด 951) — รอจนเสร็จก่อนค่อยเริ่มค้นข้อมูล
2. ค้น DB + คลังความรู้ (956) แล้วค่อยยิง PubMed/ThaiJO (964) เป็นอีกรอบ
3. ร่างคำตอบด้วย `MODEL_MAIN` แบบ **ไม่ stream** (1050) — รอทั้งคำตอบ
4. ตรวจสอบคำตอบ (Verification, 1113) ด้วย `MODEL_MAIN` อีกครั้ง — อ่านคำตอบทั้งฉบับ + CONTEXT ทั้งก้อน
5. เพิ่งส่งออกเป็น SSE ปลอม (1157) โดยหั่นข้อความที่ได้มาแล้วทีละ 60 ตัวอักษร

รวมแล้วผู้ใช้ต้องรอ ~3 รอบโมเดล + 2 รอบเครือข่ายภายนอก ก่อนเห็นตัวอักษรแรก

## แผนแก้ (คงคุณภาพเดิม)

### 1. Stream คำตอบจริง (ผลชัดที่สุด)
เปลี่ยนการร่างคำตอบเป็น `stream: true` แล้ว pipe ตรงไปหาหน้าเว็บ — ผู้ใช้เห็นตัวอักษรแรกภายใน ~1–2 วินาที แทนที่จะรอทั้งฉบับ (เวลารอที่ "รู้สึกได้" ลดลงมากที่สุดในทุกข้อ)

### 2. เปลี่ยน Verification เป็นแบบไม่บล็อกผู้ใช้
ปัญหาคือ ถ้า stream แล้วจะตรวจก่อนส่งไม่ได้ จึงปรับเป็น **ตรวจแบบเบา ๆ ก่อน + ตรวจเต็มเฉพาะเมื่อเสี่ยง**:
- ตรวจด้วยโค้ด (ไม่ใช้โมเดล, ~0 วินาที) ระหว่าง/หลัง stream: ชื่อยา-ตำรับที่ถูกอ้างอิงมีอยู่ใน CONTEXT จริงไหม, PMID/ลิงก์มาจาก CONTEXT ไหม, คำถามขอรายชื่อแล้วตอบครบไหม, มีการปฏิเสธผิดพลาดไหม
- เรียกโมเดลตรวจ (LLM verification) **เฉพาะเมื่อโค้ดจับสัญญาณผิดปกติ** ถ้าพบว่าต้องแก้ ให้ส่งคำตอบฉบับแก้ไขต่อท้ายใน stream เดียวกัน (หน้าเว็บแสดงแทนที่ของเดิม)
- ผลลัพธ์: คำตอบส่วนใหญ่ที่ถูกต้องอยู่แล้วจะไม่ต้องเสียเวลารอตรวจอีกรอบเลย ส่วนคำตอบที่เสี่ยงยังถูกตรวจเหมือนเดิม

### 3. ยิง Intent + ค้นข้อมูลพร้อมกัน
เริ่มค้น DB/คลังความรู้ด้วยคำถามดิบ **ทันที** พร้อมกับที่เรียก intent classifier แล้วค่อยเสริมผลจาก intent (อาการ/ชื่อยาที่สกัดได้) เข้าไป — ประหยัดเวลารอ classifier ทั้งก้อน (~0.5–1 วิ)

### 4. ยิง PubMed/ThaiJO ขนานกับการค้นในระบบ
ตอนนี้ต้องรอผล DB ก่อนถึงจะสร้าง query ภายนอกได้ ปรับเป็นสร้าง query จากคำถาม+intent แล้วยิงขนานไปพร้อมกับ DB ทันที (ยังคง timeout 4 วิเดิม) — ประหยัดอีก ~1–3 วิ

### 5. ใช้โมเดลให้เหมาะกับงาน
- ขั้นตรวจคำตอบ (เมื่อถูกเรียก) และ AI fallback → ใช้ `google/gemini-3.6-flash` หรือ flash-lite แทน `MODEL_MAIN` ตัวเต็ม
- คงโมเดลหลักที่ร่างคำตอบไว้เท่าเดิม เพื่อไม่ให้คุณภาพคำตอบลด
- เปิด fast mode (`service_tier: "priority"`) ให้การเรียกโมเดลหลัก เพื่อลด latency

### 6. ลดขนาด CONTEXT ที่ส่งเข้าโมเดล
ตัดเนื้อหาเอกสารคลังความรู้ให้เหลือช่วงที่เกี่ยวข้อง และตัด field ที่ไม่ได้ใช้ตอบออกจากรายการ herbs/formulas — context สั้นลง = โมเดลเริ่มพ่นคำตอบเร็วขึ้น โดยข้อมูลที่ใช้อ้างอิงยังครบ

## ไฟล์ที่แก้
- `supabase/functions/herbal-chat/index.ts` (หลักทั้งหมด)
- `src/pages/ChatPage.tsx` (รองรับกรณีคำตอบถูกแก้หลัง stream + ข้อความสถานะ)

## ผลที่คาดหวัง
- เห็นตัวอักษรแรก: ~1–3 วินาที (จากเดิมต้องรอจนจบทุกขั้น)
- คำตอบจบครบ: ลดลงราว 40–60% จากปัจจุบัน
- ความถูกต้อง: เท่าเดิม — การตรวจสอบยังอยู่ครบ เพียงแต่ทำเฉพาะเมื่อจำเป็น

## การทดสอบ
ยิงคำถามจริงผ่านฟังก์ชันอย่างน้อย 5 แบบ (ถามชื่อยา, ถามอาการ, ขอรายชื่อตำรับ, ถาม drug interaction, คำถามนอกขอบเขต) จับเวลาเทียบก่อน/หลัง และตรวจ log ว่าคำตอบยังถูกต้องและอ้างอิงครบ
