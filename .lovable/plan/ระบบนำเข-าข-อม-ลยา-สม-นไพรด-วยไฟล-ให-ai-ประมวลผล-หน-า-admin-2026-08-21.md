# ระบบนำเข้าข้อมูลยา/สมุนไพรด้วยไฟล์ + ให้ AI ประมวลผล (หน้า Admin)

ตอนนี้หน้า Admin มี "คลังความรู้" ที่พิมพ์เนื้อหาเองได้เท่านั้น ยังไม่มีช่องทางแนบไฟล์ แผนนี้เพิ่มการอัปโหลดไฟล์เอกสารยา แล้วให้ Gemini อ่าน สรุป และแปลงเป็นข้อมูลที่บันทึกลงฐานข้อมูลได้เลย

## สิ่งที่ผู้ใช้จะได้

1. แท็บใหม่ในหน้า Admin: "นำเข้าข้อมูลยา (Import)"
  - ลากวางหรือเลือกไฟล์: PDF, Word (.docx), Excel/CSV, ข้อความ (.txt/.md) และรูปภาพหน้าเอกสาร (jpg/png)
  - รองรับอัปโหลดหลายไฟล์ต่อครั้ง
2. ระบบส่งไฟล์ให้ AI อ่านและแยกข้อมูลออกเป็นโครงสร้าง เช่น ชื่อไทย/อังกฤษ/วิทยาศาสตร์ สรรพคุณ ขนาดใช้ วิธีใช้ ข้อควรระวัง ข้อห้ามใช้ ปฏิกิริยากับยาแผนปัจจุบัน ส่วนประกอบตำรับ
3. หน้าตรวจทานก่อนบันทึก (สำคัญ): แสดงรายการที่ AI แยกได้เป็นการ์ด/ฟอร์ม แก้ไขได้ทุกช่อง เลือกได้ว่าจะบันทึกลง
  - ตารางสมุนไพรเดี่ยว (herbs)
  - ตารางตำรับยาแผนไทย (thai_formulas)
  - คลังความรู้ (knowledge_documents) สำหรับเนื้อหาบทความ/แนวทาง
   พร้อมเตือนเมื่อชื่อซ้ำกับข้อมูลเดิม (เลือกอัปเดตทับหรือข้าม)
4. เก็บไฟล์ต้นฉบับไว้อ้างอิง และแสดงประวัติการนำเข้า (ชื่อไฟล์ วันเวลา จำนวนรายการ สถานะ)  
5. เพิ่มระบบ version ของฐานข้อมูลยาด้วย และสามารถย้อนหลังกลับไปใช้ version เดิมได้

## ทางเลือกการนำเข้าอื่นที่รวมไว้ด้วย

- วาง/แปะข้อความยาว ๆ แล้วให้ AI แยกโครงสร้างให้ (ไม่ต้องมีไฟล์)
- ดาวน์โหลดเทมเพลต CSV เพื่อกรอกข้อมูลจำนวนมากแล้วอัปโหลดตรง ไม่ต้องผ่าน AI

## รายละเอียดทางเทคนิค

- Storage: สร้าง bucket `imports` (private) เก็บไฟล์ต้นฉบับ
- ตารางใหม่ `import_jobs`: file_name, file_path, status, extracted (jsonb), error, created_at/updated_at พร้อม GRANT + RLS (อ่าน/เขียนผ่าน service_role จาก edge function; อ่านสาธารณะแบบเดียวกับตารางแอดมินปัจจุบันของโปรเจกต์)
- Edge function ใหม่ `import-drug-data`:
  - รับ file path จาก storage → แปลงเป็นข้อความ (PDF/DOCX/CSV/TXT แปลงในฟังก์ชัน; รูปภาพส่งเป็น image ให้โมเดลอ่าน)
  - เรียก Lovable AI Gateway ด้วย `google/gemini-3-flash-preview` แบบ tool/structured output ตาม JSON schema ที่ตรงกับคอลัมน์ของ herbs / thai_formulas / knowledge_documents
  - ไฟล์ยาวใช้การแบ่งเป็นชิ้น (chunk) แล้วรวมผล; ใส่ timeout และคืน error ที่อ่านเข้าใจได้
  - ไม่บันทึกลง DB เอง — คืนผลให้แอดมินตรวจทานก่อน
- Edge function `import-commit` (หรือรวมเป็น action เดียวกัน): รับข้อมูลที่แอดมินยืนยันแล้ว upsert ลงตารางเป้าหมายด้วย service_role
- Frontend: คอมโพเนนต์ `DataImporter.tsx` (อัปโหลด → สถานะประมวลผล → ตารางตรวจทาน → บันทึก) เพิ่มเข้าไปในหน้า Admin ข้าง KnowledgeManager ใช้ธีมไทยสมุนไพรเดิม
- ข้อมูลที่นำเข้าจะถูกบอทใช้ตอบทันที เพราะ `herbal-chat` ค้นจากตารางเหล่านี้อยู่แล้ว (มี cache 5 นาที)

## ลำดับการทำ

1. Migration: ตาราง `import_jobs` + bucket `imports`
2. Edge function ประมวลผลไฟล์ด้วย Gemini (structured output)
3. Edge function บันทึกข้อมูลที่ยืนยันแล้ว
4. UI `DataImporter.tsx` + ต่อเข้าในหน้า Admin
5. ทดสอบด้วยไฟล์ PDF/CSV ตัวอย่าง และตรวจว่าบอทตอบจากข้อมูลใหม่ได้
