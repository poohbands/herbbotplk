# ระบบจัดการผู้ให้บริการ AI และสลับอัตโนมัติเมื่อล่ม

ให้ผู้ดูแลตั้งค่าผู้ให้บริการ AI ได้หลายเจ้า (Gemini, DeepSeek, OpenRouter, Qwen) เรียงลำดับความสำคัญ ถ้าเจ้าแรกล่มหรือโควตาหมด ระบบจะสลับไปเจ้าถัดไปให้เองโดยผู้ใช้ทั่วไปไม่รู้สึกถึงความต่าง

## สิ่งที่ผู้ใช้จะได้

- หน้าใหม่ในส่วนผู้ดูแล: "ตั้งค่า AI" (`/admin/ai-settings`) เข้าได้หลังใส่รหัสผ่านเดิมเท่านั้น
- รายการผู้ให้บริการแต่ละเจ้า พร้อม
  - สวิตช์เปิด/ปิดใช้งาน
  - ลำดับความสำคัญ (1 = ใช้ก่อน, 2 = สำรอง ...) พร้อมปุ่มเลื่อนขึ้น/ลง
  - ช่องแก้ชื่อโมเดล และที่อยู่ปลายทาง (Base URL)
  - ช่องใส่กุญแจ API พร้อมปุ่มซ่อน/แสดง (ค่าที่บันทึกแล้วจะแสดงเป็นดาวเสมอ ไม่ส่งกลับมาที่หน้าเว็บ)
  - ปุ่ม "ทดสอบการเชื่อมต่อ" ยิงคำถามสั้น ๆ จริง แล้วแจ้งผลสำเร็จ/ผิดพลาดทันที
  - ปุ่ม "บันทึก" พร้อมสถานะกำลังบันทึกและข้อความแจ้งผล
- หน้าแชทของประชาชนทำงานเหมือนเดิมทุกอย่าง (พิมพ์ตอบทีละคำ อ้างอิงแหล่งข้อมูล ตรวจสอบคำตอบ) เพียงแต่เบื้องหลังจะเลือกผู้ให้บริการตามลำดับที่ตั้งไว้
- ถ้าทุกเจ้าล่มพร้อมกัน จะขึ้นข้อความสุภาพว่าระบบให้คำปรึกษาไม่พร้อมใช้งานชั่วคราว กรุณาลองใหม่อีกครั้ง

## ข้อสำคัญเรื่องความปลอดภัย

คุณเลือกคงรหัสผ่านผู้ดูแลแบบเดิม (ไม่มีระบบบัญชีผู้ใช้) จึงไม่สามารถใช้กฎ "เฉพาะผู้ใช้ที่มีสิทธิ์ admin" ในฐานข้อมูลได้ตามที่ระบุไว้ในโจทย์ แนวทางที่จะใช้แทนคือ **ปิดการเข้าถึงตารางนี้จากหน้าเว็บทั้งหมด** กุญแจ API จะอ่าน/เขียนได้เฉพาะฝั่งเซิร์ฟเวอร์ที่ตรวจรหัสผ่านผู้ดูแลก่อนเท่านั้น กุญแจจะไม่ถูกส่งกลับมาแสดงในเบราว์เซอร์เลย

ระดับความปลอดภัยยังต่ำกว่าการมีระบบบัญชีผู้ใช้จริง (ใครรู้รหัสผ่านก็แก้ได้) ถ้าต้องการยกระดับภายหลัง เพิ่มระบบล็อกอินได้ทีหลังโดยไม่ต้องรื้อส่วนนี้

## รายละเอียดทางเทคนิค

**ฐานข้อมูล** — ตาราง `public.ai_providers`: `id`, `name`, `provider_key` (unique), `api_key`, `base_url`, `model_name`, `is_active` (default false), `priority` (default 1), `created_at`, `updated_at` + trigger อัปเดตเวลา
- เปิด RLS แต่ **ไม่มี policy ใด ๆ** และไม่ GRANT ให้ `anon`/`authenticated` → เข้าถึงไม่ได้จากหน้าเว็บ; `GRANT ALL ... TO service_role` สำหรับฝั่งเซิร์ฟเวอร์
- Seed แถวปิดใช้งานไว้: Google Gemini (`generativelanguage.googleapis.com/v1beta/openai`, `gemini-2.5-flash`, priority 1), DeepSeek (`api.deepseek.com`, `deepseek-chat`, 2), OpenRouter (`openrouter.ai/api/v1`, `deepseek/deepseek-chat`, 3), Qwen (DashScope compatible-mode, `qwen-plus`, 4)
- เก็บรหัสผ่านผู้ดูแลเป็น secret `ADMIN_PASSWORD` (ค่า sakura4923) เพื่อให้ฝั่งเซิร์ฟเวอร์ตรวจได้

**Edge Function ใหม่ `ai-providers-admin`** (service role) — actions: `list` (คืนข้อมูลโดยแทน `api_key` ด้วยแค่ flag ว่ามีคีย์แล้วหรือยัง), `save` (อัปเดตหลายแถว; คีย์ว่าง = ไม่เปลี่ยนของเดิม), `test` (ยิง prompt สั้นไปยัง endpoint ของเจ้านั้นแล้วคืนสำเร็จ/ข้อความ error) — ทุก action ต้องแนบรหัสผ่านผู้ดูแลและตรวจกับ `ADMIN_PASSWORD` ก่อน

**ตัวเรียก AI พร้อม failover** — เพิ่มโมดูลใช้ร่วม `supabase/functions/_shared/ai-router.ts`
- โหลดผู้ให้บริการที่ `is_active = true` เรียงตาม `priority ASC` (cache สั้น ๆ ในหน่วยความจำ)
- ส่งแบบ OpenAI-compatible `/chat/completions` ทุกเจ้า (Gemini ใช้ compatible endpoint ของ Google) รองรับทั้งแบบ stream และไม่ stream พร้อม timeout
- วนลองเจ้าถัดไปเมื่อเจอ 401/403/429/5xx/timeout และ log ไว้ฝั่งเซิร์ฟเวอร์; ถ้าไม่มีเจ้าไหนใช้ได้เลย ให้ย้อนกลับไปใช้ AI ภายในระบบเดิม (Lovable AI) เป็นด่านสุดท้าย และถ้ายังไม่ได้จึงคืน 503 พร้อมข้อความสุภาพ
- `supabase/functions/herbal-chat/index.ts` เปลี่ยนทุกจุดที่เรียก AI (จำแนกคำถาม / ตอบหลักแบบ stream / ค้นข้อมูลสำรอง / ตรวจคำตอบ) ให้ผ่าน router ตัวนี้ โดยคง persona เภสัชกร/แพทย์แผนไทย, RAG, การอ้างอิงแหล่งข้อมูล และคำเตือนให้ปรึกษาแพทย์ไว้ครบเหมือนเดิม
- โจทย์ระบุชื่อฟังก์ชัน `chat-pharmacist` แต่จะคงชื่อ `herbal-chat` เดิมไว้เพื่อไม่ให้หน้าแชทที่ใช้งานอยู่สะดุด (ตรรกะตรงตามที่ระบุทุกข้อ)

**หน้าเว็บ** — `src/pages/AiSettingsPage.tsx` + route `/admin/ai-settings` ป้องกันด้วย `AdminLogin` เดิม (เก็บสถานะเดียวกับหน้า `/admin`) และเพิ่มลิงก์เข้าจากหน้าผู้ดูแล ใช้ shadcn Switch/Input/Button/Card + toast ตามธีมเดิม

**ทดสอบ** — กด "ทดสอบการเชื่อมต่อ" ของเจ้าที่ใส่คีย์แล้วต้องขึ้นสำเร็จ, ปิดเจ้าอันดับ 1 หรือใส่คีย์ผิดแล้วถามในหน้าแชท ต้องได้คำตอบจากเจ้าสำรองโดยผู้ใช้ไม่เห็นความต่าง, และตรวจ log ว่ามีการสลับจริง
